## Design Specificity Verdict

### LLM assessment

The product structure is authored rather than generic: agent-specific prompt chips, registry-driven context tabs, analytics onboarding, knowledge sessions, and asset workspaces give Kawai a real product model. The visual expression is less distinctive. A blue Tea/shadcn shell with compact rounded controls, icon rails, a right session list, and a centered composer could be transplanted into another AI workspace with little change. Kawai's differentiator is currently its information architecture, not a memorable visual signature.

The shell also carries three visual dialects: Tea asset-management surfaces, shadcn controls, and custom agent/chat styling. The tokens are centralized in `frontend/src/index.css`, which is a good foundation, but many components still express the system directly through mixed utility patterns and raw Tea variables.

## Overall Impression

Kawai is a thoughtful agent workspace with stronger product composition than its current visual hierarchy suggests. The center conversation is the reason to be here, but on desktop it competes with too many equally assertive surfaces and controls. The biggest opportunity is to make the conversation unmistakably dominant, then let context and session management appear as deliberate utility surfaces rather than permanent visual peers.

## What's Working

1. **Agent composition is meaningfully product-specific.** `contextTabsFor`, `agentPresentation`, and `useContextOnboarding` change the workflow for Office, Analytics, and other agents instead of only changing labels.
2. **System feedback is unusually present.** Model warming, streaming, history errors, indexing, retry, stop, archive, and empty states are represented in the interface.
3. **Responsive intent is sound.** Desktop rails become drawers below `md`, with backdrop and Escape dismissal, while the composer and conversation remain the mobile anchor.

## Priority Issues

### [P1] The desktop shell makes the conversation compete with three navigation surfaces

**Why it matters:** At common laptop widths, the 210px agent rail, 240px session panel, and context canvas leave the actual conversation and composer with too little horizontal authority. Users must parse agents, assets, sessions, knowledge tabs, and chat at the same time.

**Fix:** Establish a minimum readable width for the conversation. At medium desktop widths, turn the context pane into a capped overlay/drawer and make Sessions utility-only when Canvas is open. Keep the agent rail narrow by default and preserve one dominant reading column.

**Suggested command:** `$impeccable layout`

### [P1] Icon-only controls hide important state and navigation

**Why it matters:** The header can expose agents, sessions, knowledge, thinking, canvas, and session-collapse actions as icons. Titles are not a replacement for visible labels, especially for touch users and people who do not know the product's shortcuts.

**Fix:** Use visible labels for Thinking, Canvas, and Sessions at desktop widths where space allows. Keep icon-only controls in the mobile header. Use an overflow menu for secondary actions and preserve explicit `aria-pressed`/`aria-expanded` state.

**Suggested command:** `$impeccable clarify`

### [P1] Session actions are not continuously discoverable

**Why it matters:** `SessionRow` hides rename/archive/delete with `opacity-0` until hover or focus. This weakens keyboard visibility and leaves touch users without a hover affordance. The two-click timed delete is also easy to misunderstand and has no Undo.

**Fix:** Keep a subtle action affordance visible on touch/narrow layouts, reveal actions on `:focus-within`, and replace timed two-click deletion with a visible inline confirmation or a toast with Undo.

**Suggested command:** `$impeccable harden`

### [P1] The interface has no resolved language or copy voice

**Why it matters:** English shell labels are mixed with Indonesian recovery and confirmation copy, while Analytics prompt chips use Indonesian alongside English domain language. This makes the product feel unfinished and reduces confidence at high-stakes moments.

**Fix:** Choose one default locale for the frontend, then route labels, errors, empty states, status text, tooltips, and prompt chips through one copy layer. Keep CSV, parquet, RSI, and MACD, but explain domain terms at first use.

**Suggested command:** `$impeccable clarify`

### [P2] Kawai is structurally specific but visually interchangeable

**Why it matters:** The Tea blue palette and generic rounded-card conventions do not yet express the calm local-agent workspace, durable context, and domain-tool character that distinguish Kawai.

**Fix:** Preserve the token foundation but define one restrained Kawai signature: agent-aware semantic accents, a stronger editorial type scale, and a distinctive active-agent treatment. Consolidate shell styling behind shared primitives instead of mixing raw Tea variables and one-off utility combinations.

**Suggested command:** `$impeccable bolder`

## Cognitive Load Assessment

- **Single focus — failed:** conversation competes with Agents, Assets, Sessions, and Knowledge.
- **Chunking — failed:** the rail and header expose too many simultaneous groups and actions.
- **Grouping — pass:** panels, tabs, cards, and borders generally group related content.
- **Visual hierarchy — failed:** similar border/background weights give secondary surfaces too much authority.
- **One thing at a time — pass:** onboarding and confirmation are reasonably sequenced.

## Persona Red Flags

### Alex — Impatient Power User

- Useful shortcuts exist (`⌘1`, `⌘2`, `⌘3`, ArrowUp), but they are discoverable mainly through button titles rather than a visible shortcut affordance.
- Session management is one item at a time: no bulk archive/delete, multi-select, or fast session command path.
- Opening the context canvas reduces the conversation's reading width and makes long tool output slower to scan.

### Sam — Accessibility-Dependent User

- Session row actions are opacity-hidden until hover/focus; focus visibility should be verified explicitly across keyboard navigation and dark mode.
- Important header toggles are icon-first and rely on titles; visible labels and persistent state would reduce interpretation cost.
- Active, success, warning, and destructive states use color heavily, so text/icon status must remain present and contrast-tested in both themes.

### Casey — Distracted Mobile User

- Agent, session, and knowledge navigation is concentrated in the top header, outside the easiest thumb zone.
- The knowledge drawer is `w-[360px] max-w-[90vw]`, leaving little working width on a phone.
- After returning from a drawer, there is no compact persistent cue that indicates which context mode was last active.

## Minor Observations

- `SessionsPanel` uses a very small header; the relationship between the current agent and its sessions could be clearer even when the agent rail is expanded.
- `ContextPanel` mixes `Link`/`Add files`, `Documents`, `Library`, `In this session`, and `Databases`; a small terminology pass would make the mental model cleaner.
- The Analytics empty state presents two similarly weighted actions; make import the primary path and database connection the secondary path.
- The global active-button scale transform is applied broadly; verify dense icon controls do not feel noisy.
- Vendored streamdown detector findings should be reviewed where actual markdown/tool output renders, not only in isolation.
