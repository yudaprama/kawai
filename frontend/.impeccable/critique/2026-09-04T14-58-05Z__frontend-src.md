## Design Specificity

The interface is meaningfully authored for Kawai: supervisor workflow, tool-result canvas, sessions, knowledge/file references, agent-specific context, and mobile drawers create a distinctive AI workbench. The primary risk is density: agent rail, asset rail, chat, canvas, knowledge, sessions, tools, and plan state can become several consoles stitched together. ## Strengths

- Centralized plan, confirmation, session, mobile drawer, and asset-workspace state.
- Composer supports mentions, pasted-image ingestion, speech, repeat-last-message, and stop behavior.
- Responsive drawers and Escape/back behavior are treated as first-class interactions.

## Priority Issues

### [P1] Too many places for one task
Define one dominant flow: Ask → Observe plan → Review result → Save/share output. Reveal secondary surfaces progressively. Suggested: `$impeccable distill`.

### [P1] Canvas, Knowledge, Assets, and Sources compete as concepts
Use user-facing labels such as Work, Files, Sessions, and Data sources; retain implementation names in code. Suggested: `$impeccable clarify`.

### [P1] Status is fragmented
Add a persistent activity strip near the header/composer with operation, step, waiting state, cancel/retry, and output link. Suggested: `$impeccable layout`.

### [P1] First-time primary action is under-explained
Explain that users ask naturally, Kawai proposes steps, and sensitive actions require approval; show 2–3 contextual examples. Suggested: `$impeccable onboard`.

### [P2] Mobile drawer reachability
Retain drawers but add bottom-sheet affordances for frequent Files/Sessions actions and preserve active-operation state. Suggested: `$impeccable adapt`.

### [P2] Error recovery is not local enough
Attach Retry/Edit/Retry indexing/Test connection actions to the failed object while preserving input and completed steps. Suggested: `$impeccable harden`.
